AGENTS.md model routing is one line — frontier model authors plugin/skill PROSE (synthesis); cheap models run validation/lint/catalog-sync (classification). When a more-capable model appears (e.g. Fable 5, at ~2x Opus pricing), place it by that split; do NOT reflexively upgrade every call site. It belongs in the frontier-synthesis + long-horizon-agentic slots: /forge grill+plan, /design grill, meta-generator prose, the self-reflection lesson generator (all run on the SESSION model, so 'use it here' means running Claude Code on it while authoring/generating), and above all an un-parked autonomous executor / agent DAG (Fable is unrivaled at long-horizon autonomous runs + async sub-agent delegation). It must stay OUT of the classification loop: the activation/delegation judge is deliberately claude-haiku-4-5 (OBJECTCORE_JUDGE_MODEL) because routing is classification run against the WHOLE catalog surface pool, per-plugin, in a majority-of-3 flake-absorption loop, on every gate/CI run — a pricier frontier model there is many-x the tokens for work the doctrine routes to cheap, and it never belongs anywhere in the `bun run check` CI path. Two hard wiring caveats if a Fable-tier model is ever wired into factory code: (1) its `refusal` stop reason targets bio + most cyber and can false-positive on this security-adjacent repo (OIDC/credential/provenance gating) — ship server-side fallbacks to claude-opus-4-8; (2) it requires 30-day retention, so a ZDR org 400s every request. Also: it always thinks (omit the thinking param; an explicit disabled 400s), which further argues against the tight structured-output judge loop. Keep the ports+adapters discipline — add a Fable-backed adapter selected by env, do not swap the default.
